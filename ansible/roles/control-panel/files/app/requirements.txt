# Control panel dependencies — PINNED, and this file IS the lock: what gets deployed is
# exactly what is written here. Same discipline as the digest-pinned container images
# and the harness's uv.lock.
#
# These were previously unconstrained. pip does not upgrade an already-satisfied
# unconstrained requirement, so the venv sat on whatever the first deploy happened to
# resolve — and deleting the venv would have silently jumped every package. That is the
# identical accidental freeze the `:latest` images had, and it is not theoretical here:
# **fastapi 0.137 is what broke vLLM's metrics instrumentation** (DEF-0005, which we
# still carry a derived container image to work around). The panel was sitting one
# patch release below it, by luck rather than by decision.
#
# Transitives are pinned too, deliberately. DEF-0005 was itself a transitive
# incompatibility (fastapi x prometheus-fastapi-instrumentator) — pinning only the
# direct five would leave exactly that hole open.
#
# To bump: edit the direct dependency, delete the venv on the head, re-deploy, then
# refresh the resolved set below from:
#   /opt/cluster/control-panel/venv/bin/pip list --format=freeze
# See skills/version-discovery/SKILL.md.
